# EOTor Engine — v3.4

**مدیر چند‌مکانه پراکسی سوکس — یک فایل، بدون نیاز به نصب**

EOTor Engine یک ابزار خط فرمان (TUI) تک‌فایله به زبان Python است که روی سرورهای Linux/Debian اجرا می‌شود و مدیریت کامل نودهای پراکسی SOCKS5 چندمکانه را از یک رابط منویی رنگی فراهم می‌کند.

---

## نیازمندی‌ها

| مورد | جزئیات |
|------|---------|
| سیستم‌عامل | Ubuntu 20.04+ / Debian 10+ |
| دسترسی | root |
| Python | 3.8+ (معمولاً از پیش نصب است) |
| پکیج‌ها | `tor`, `tor-geoipdb`, `curl` — از داخل برنامه نصب می‌شوند |

---

## نصب و راه‌اندازی

```bash
# دانلود فایل
wget https://raw.githubusercontent.com/EOAMIR/eotor/main/eotor.py

# اجرا
sudo python3 eotor.py
```

بعد از اولین اجرا، برنامه خودش را به عنوان دستور سیستمی ثبت می‌کند:

```bash
sudo eotor
```

از منوی اصلی گزینه **[1] Setup & Engine** → **[1] Install Engine** را بزنید تا وابستگی‌ها نصب شوند.

### 4 — Control Modules

| گزینه | عملکرد |
|-------|---------|
| Start modules | استارت نودهای انتخابی با ID |
| Stop modules | توقف نودهای انتخابی |
| Restart modules | ری‌استارت نودهای انتخابی |
| Start ALL modules | استارت همه نودهای نصب‌شده |
| Stop ALL modules | توقف همه نودهای نصب‌شده |
| Restart ALL modules | ری‌استارت همه نودهای نصب‌شده |
| Remove modules | حذف نودهای انتخابی (با ID) |
| Remove ALL modules | حذف همه نودها با تأیید کاربر |

> پشتیبانی از هر دو محدوده: مکان‌های اصلی (1–50) و گسترده (51+)

### 5 — Monitoring & Diagnostics

| گزینه | عملکرد |
|-------|---------|
| Live status table | جدول کامل وضعیت همه نودها: نصب‌شده / در حال اجرا / متوقف، پورت، تعداد رله |
| Health check | تست اتصال زنده روی همه نودهای فعال با curl و نمایش زمان پاسخ (ms) |
| Refresh relay density | دریافت مجدد تعداد رله‌های خروجی هر کشور از شبکه |
| Show exit IP per location | نمایش IP خروجی واقعی هر نود از طریق SOCKS5 |
| Diagnose a node | بررسی لاگ systemd و وضعیت یک نود مشخص برای عیب‌یابی |

**رنگ‌بندی رله‌ها در لیست مکان‌ها:**
- سبز: بیش از 10 رله (ایده‌آل)
- زرد: 3 تا 9 رله (محدود)
- قرمز: کمتر از 3 رله (بحرانی)

### 6 — IP & Routing

| گزینه | عملکرد |
|-------|---------|
| Deploy module (with progress) | استقرار یک نود با نوار پیشرفت زنده و نمایش درصد bootstrap |
| Live IP panel | پنل real-time که IP خروجی همه نودهای فعال را به‌صورت زنده نمایش می‌دهد |
| Rotate IP | چرخش مدار (circuit refresh) برای تغییر IP خروجی نودهای انتخابی |

---

### 7 — Automation & Guardian

#### Auto-restart

| گزینه | عملکرد |
|-------|---------|
| Enable hourly auto-restart | ایجاد systemd timer که هر ساعت همه نودها را ری‌استارت می‌کند |
| Disable hourly auto-restart | حذف timer و service مربوطه |

#### CPU Guardian

سرویس پس‌زمینه که هر 5 دقیقه CPU همه نودها را چک می‌کند:

- اگر CPU یک نود از **80%** بیشتر شود → نود متوقف می‌شود
- بعد از **1 ساعت** → نود خودکار ری‌استارت می‌شود
- لاگ رویدادها قابل مشاهده است

| گزینه | عملکرد |
|-------|---------|
| Start CPU Guardian | شروع نظارت پس‌زمینه |
| Stop CPU Guardian | توقف Guardian |
| Guardian status & event log | نمایش وضعیت و لیست نودهایی که متوقف شده‌اند |

## منطق استقرار نود

هر بار که نودی نصب می‌شود:

1. **تلاش سریع** — تا 8 بار با timeout کوتاه (7 ثانیه)
2. **در صورت شکست** — رفتن به حالت `StrictNodes 0` (relaxed) با timeout بلندتر (60–120 ثانیه)
3. **تأیید اتصال** — curl به Google از طریق SOCKS5
4. **بررسی پایداری** — 2 چک متوالی برای اطمینان از ثبات IP
5. **گزارش نهایی** — SUCCESS / FAILED / RETRIED / WARNED

در استقرار موازی، یک thread جداگانه نوار پیشرفت کل عملیات را به‌صورت زنده نمایش می‌دهد.
